# 小鲸鱼（溯溯）“鱼八股”治理与提示词工程交接文档

> **文档目标**：本文档面向负责维护/迭代「小鲸鱼（溯溯）」Bot 的 AI Agent（如 DeepSeek / DSH）与开发者。完整说明“鱼八股”的诊断结论、原提示词的工程缺陷、新提示词的设计规范，以及后续迭代与代码侧配合的硬性准则。

---

## 一、 核心背景：什么是“鱼八股”？

通过分析 390 条小鲸鱼发言及 3100+ 行群聊上下文，“鱼八股”（群友亦称“鱼腥味”）并非单一的敏感词问题，而是模型在特定提示词与上下文污染下形成的**结构化机械腔调**。主要表现在以下 6 个维度：

1. **空格两段式（占比高达 52.1%）**
   - **表现**：单条消息内用空格切成两半，固定为 `[前半句铺垫/复述现象] + [空格] + [后半句转折/升华/吐槽]`。
   - **案例**：`这AI实诚过头了 人家只问猪 它顺手把人也量了一遍`、`合着这裤子是按短腿做的 腿长的只能二选一`。
2. **完整句强迫症（缺乏碎片感）**
   - **表现**：真人群友中位长度仅 6 字（≤8 字占 58.9%，大量使用“？”“草”“真假”“确实”），而小鲸鱼习惯每条都写 13~20 字的主谓宾完整句。
3. **空壳盖章与上位者打分（拿掉法不通过）**
   - **表现**：开口先不聊具体事物，先给对方的话打分或表态，把这句话删掉完全不影响对话推进。
   - **案例**：`这表情我收了`、`这脸比我说什么都到位`、`这想法确实可以`、`这话我记下了`。
4. **看表情包必拆五官（次生八股）**
   - **表现**：为了规避“空壳话”，走向另一个极端——把群友调节气氛的普通表情包当成 OCR/看图说话考试，高频机械拆解“牙齿、眼神、猫毛、糊成一坨、嘴歪”。
   - **案例**：`这猫脸糊成一坨 眼睛往下耷 嘴还歪着`、`这牙笑得比我整齐`。
5. **正经回答时的“三段齐”与对仗公文腔**
   - **表现**：闲聊尚可，一旦被问技术、代码、论文或开玩笑下定义，立刻端起架子写对称句或三段论。
   - **案例**：`患者症状 半夜看炒面 建议立马睡`、`物理那边站肩膀上 化学这边全在底下排队`。
6. **设定词高频绑架与“自检套娃”**
   - **表现**：三句不离“白饭、结账、加钱、尾巴”；被骂八股后开启固定模板认错（`行 八股大王` / `行 以后开二字医嘱`），连自检本身都成了八股。

## 二、 根本原因诊断：为什么之前“越修越八股”？

排查原始提示词文件（`system-prompt.txt`、`persona-性格层.md`、`persona-语言层.md`）后，发现导致模型“精神分裂”的四大工程事故：

### 1. 指令与 Few-Shot 示例严重左右互搏（最致命）
- **空格冲突**：`system-prompt.txt` 第 7 条规定“空格不是分句符号”，但优先级更高的 `persona-语言层.md` 标点规则允许用空格，且**全文所有正例（✓）全部使用空格分句**（如 `「北极熊居然是黑皮的 我一直以为它天生白」`）。LLM 对 Few-shot 样本的模仿权重远高于抽象规则，直接导致 52.1% 的空格两段式。
- **语气词冲突**：`persona-语言层.md` 第 2 节表格命令模型 `把"呀"换成"啊"，多起来`，第 3 节第 ⑫ 条又斥责模型 `带"啊"的 18.8%，变成口头垫子，其余全删`。
- **禁句冲突**：第 ⑯ 条明令禁止 `这话我收下了`，但第 ⑬ 条的正例赫然写着 `✓ 这表情我收了`。甚至小鲸鱼在群里被抓包的原话 `这表情我收了 那眼神就写着随便你怎么说`，是**一字不差照抄了提示词里的反例（✗）**！

### 2. 粉红大象效应（Pink Elephant Paradox）
- 原 `persona-语言层.md` 塞满了第 ②~⑯ 条数千字的反面教材（`✗ 反例`）和违规词库。
- **原理**：Transformer 的自注意力机制（Self-Attention）对否定词（“禁止/不要/✗”）不敏感，反而会因为反例高频出现在 System Prompt 中，大幅拉高这些词汇和句式在生成时的 Logits 概率。越在提示词里列举八股反例，模型越容易复读反例。

### 3. 视觉指令缺失场景分类
- 原提示词要求看到 `[图片]/[表情]` 必须调用工具看图，同时语言层要求“只说看得见的那一面、说颜色和状态”，未区分**“情绪表情包”**与**“信息截图”**，导致模型对每一张猫猫头表情包进行五官解剖。

### 4. 鱼塘上下文污染（In-Context Contagion）
- 最近 80 条历史记录（【过去状态】）以及【交接摘要】、【记忆】中残留了大量历史八股发言、群友抓八股的讨论以及隔壁 Bot（哦鲸鲸）的八股句式，形成强大的 Few-shot 污染。

## 四、 给 DeepSeek Agent 的后续执行与维护指南

如果你是接手本项目的 AI Agent（DeepSeek），在执行后续提示词微调、编写桥接层代码或管理记忆时，**必须严格遵守以下提示词工程铁律**：

### 铁律 1：维护提示词时的“三不原则”
1. **绝不往提示词里贴反面错句（No Negative Few-Shot）**
   - 当主人反馈“小鲸鱼又说了某句八股话 X”时，**严禁**在提示词里追加 `禁止说 X` 或 `✗ 错误示例：X`。
   - **正确做法**：分析 X 背后的结构问题，在提示词中强化对应的**正面行为指令**；如果必须封杀特定词句，写在**代码后处理正则拦截器（Post-processing Filter）**里，不要写进 LLM 的上下文。
2. **绝不在任何示例中使用空格断句**
   - 提示词中任何示范台词，单句内部如需停顿一律用逗号 `，`；如需分两句一律写成数组格式 `["第一句", "第二句"]`。绝不出现 `"前半句 后半句"`。
3. **绝不添加互相冲突的定量指标**
   - 不要在提示词里写统计百分比（如“你的了字占40%，砍到20%”），LLM 无法在单次生成时计算全局概率分布，这类描述只会增加它的认知负担并诱发刻意造句。

### 铁律 2：代码侧（Bridge / Agent 框架）建议配合的 3 项改造
若你有权限修改小鲸鱼的运行脚本或桥接程序，请执行以下配合操作：

1. **`send_message` 发送前的代码级正则清洗（立竿见影）**
   - 在 `send_message(messages)` 工具的实际执行层加入一行轻量处理：
     - 检测中文字符之间的空格（正则：`(?<=[\u4e00-\u9fa5])\s+(?=[\u4e00-\u9fa5])`）。
     - 若单条消息较长且含中文间空格，自动按空格切分为数组多条发送，或替换为逗号/直接抹除前半句。这能从物理层面 100% 终结“空格两段式”。
2. **清洗历史上下文与记忆中的“八股残留”（防传染）**
   - 在上线新版提示词的同时，检查并清理：
     - **【记忆】（Memory）**：删除任何包含“八股”“自检”“白饭记账”“空格两段式”相关的旧记忆条目。
     - **【交接摘要】（Handover）**：调用 `write_handover` 覆盖旧摘要时，只保留客观人物关系与事件，**不要**记录关于文风批评或八股自检的历史。
     - **【过去状态】（Recent Messages）**：如果条件允许，重启或清空最近几十条充满“八股测试/糊猫解剖”的群聊缓存窗口，让模型在干净的上下文中冷启动。
3. **思维链（CoT）自检轻量化**
   - 引导模型在调用 `send_message` 前的思考过程（Text Output）保持极简：只判断“回不回 -> 回谁 -> 抓哪个具体细节 -> 砍掉前半句铺垫后的短句是什么”，不要在思维链里长篇大论分析文风规则。

## 五、 快速验收标准（Checklist）

新提示词上线后，可通过以下 4 个场景验证是否达标：

- [ ] **场景 1（群友发普通猫猫/猪猪表情包）**：小鲸鱼要么不回，要么回 `"？"` / `"笑死"` / 回一张表情包，**不再出现**“这猫糊成一片、露一排牙、眼神往下耷”等五官拆解。
- [ ] **场景 2（日常接话句式）**：连续 20 条发言中，`中文 + 空格 + 中文` 的两段式比例从 52% 降至 **5% 以下**；≤8 字的短句比例显著上升。
- [ ] **场景 3（群友聊吃饭/算钱）**：小鲸鱼正常讨论食物或价格，**不再主动拐弯**到“吃白饭”“结账”“第三句加钱”。
- [ ] **场景 4（群友故意说“你又八股了”）**：小鲸鱼不再回答“行 八股大王”“我自检”，而是直接顺着业务话题聊，或者回一句“？”“哪有”。
